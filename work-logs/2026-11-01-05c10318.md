## Challenges and how we solved them
- **Paper frames laid out in a row.** `create_artboard` placed the frames side by side. I repositioned them into a column with `update_styles`.
- **Tinkering page truncated.** An edit script opened `tinkering/index.html` for writing before reading it, which emptied the file. It had no other uncommitted changes, so I restored it from git and reapplied the header edit.
- **Header overflowed on a phone-sized window.** Headless Chrome didn't honor the small window size. I switched to emulating a real 390px viewport, which showed the layout was fine.
- **Canvas boards blank on first frame.** The boards were drawn before being measured, so the tile size was undefined. I now measure synchronously once the board is in the page.
- **Animation appeared skipped in screenshots.** Browser animation timestamps ran ahead of the real clock. I switched to `performance.now()` and rendered frozen frames at fixed animation times to check it.
- **Canvas cleared on resize.** Resizing a canvas wipes it, so every resize now redraws immediately.
- **Promised comparison version was not saved.** I had said I'd keep the old HTML version in git history, but it was never committed. I apologized and rebuilt it as `lab/flap-html.html`.
- **Hard-to-read text on boards.** The headless screenshots could not read board text via the DOM once the boards became canvases, so I checked the visuals instead.

## Lessons learned
- Commit before replacing a working implementation if the user may want to compare it later.
- Geist Serif has one weight (Regular). For chunky split-flap letters, use Geist (sans) at 800–900, which has a real weight axis.
- Use real motion blur (shutter averaging) rather than ghost copies when the user wants a photographic look.
- Verify animations with frozen-time renders rather than real-time screenshots, which are unreliable in headless Chrome.
- Read a file before opening it for writing in edit scripts.
- Sandbox permissions block deleting branches without explicit approval.
- The user prefers a quick recommendation and short options, and likes to compare approaches side by side.
- The user likes to see the animation tuned by constants, and the exact feel is judged in their own browser.
