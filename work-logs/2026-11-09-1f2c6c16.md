**Halftone renderer** (`halftone.js`, new)
- Draws each band onto a `<canvas class="halftone">` inside its section. The canvas is centred on the edge with the section above and reaches `height/2 + bleed` px either side. `bleed()` grows with the distortions so nothing gets clipped. It sets `--halftone-reach`, which `styles.css` uses for section padding and the cover height. The CSS gradient dots were removed, so without JavaScript the band is a straight edge.
- Method: every pixel finds its nearest dot centres on a screen (grids: offset, hex or square; shapes: round, square, diamond or line). Dot radii come from a sorted distance-to-nearest-dot table, so colour coverage ramps 0 → 1 across the band (dots grow, merge, then the holes close). With "one size per dot" on, each dot takes its size from the coverage at its own centre.
- Settings (`DEFAULTS`): height, start/end, curve, cell (shown in the lab as density, in rows), dotSize, grid, shape, perDot, angle, stretch, softness; wave, ragged edge, mottle, warp, sizeTop/sizeBottom (perspective), jitter and seed; animation settings animate (mottle strength wanders between mottleMin and mottleMax), flow (px/s, sideways travel), heaveAmp/heaveLen (swells that rise and fall), rise (px/s, mottle drifts up), morph (mottle shapes per second), animPeriod and animFps. `shift` and `time` are internal, set per frame by `at(cfg, seconds)`.
- `renderer(canvas)` uses a WebGL2 fragment shader that ports the same maths, noise hash included, so output matches. It falls back to the CPU `mask()` + `paint()` path when WebGL2 is missing, and that path draws a still band only. `animate()` uses requestAnimationFrame capped at animFps (default 60).
- `mount(sections, cfg)` builds the home page canvases. It redraws on width change, animates only bands an IntersectionObserver reports as visible, pauses when the tab is hidden, and never animates under `prefers-reduced-motion`.

## Challenges and how we solved them
- **Screenshotting below the fold:** a headless `--screenshot` with a tall window also made the cover taller, because it's sized in `svh`, and `#hash` URLs didn't scroll. Fixed with a small Chrome DevTools Protocol script in the session scratchpad (`shot.mjs`, `anim.mjs`, `gl*.mjs`) that navigates, scrolls, evaluates JavaScript and captures.
- **"Symmetrical" misunderstood twice:** first the band was centred on the section edge (kept). Then a mirror style, with upper-colour dots shrinking into the lower colour, was added and reverted at the user's request. The centring stayed.
- **Dot size above 1 left stray specks:** scaling the radius back to 1 near the end made it shrink. Sizes above 1 now advance coverage instead (`t × dotSize`), so dots only ever grow.
- **Animation widened and narrowed the band:** animating the mottle scale zoomed the pattern about the centre. Scale wandering was removed and replaced with heave (vertical swells). Only flow moves anything sideways.
- **Frame rate:** the CPU renderer ran 10–14 fps even off the main thread in a worker. It was rebuilt as a WebGL2 shader and now holds 60 fps in the lab with all five bands at 4× zoom. GPU and CPU output differ by under 0.2% mean, checked with `readPixels` against `mask()`.
- **Checking the direction of rise:** per-pixel comparisons failed because the dots stay on their grid and only resize. Averaged over 24px patches, one second's frame matched the previous frame shifted up by 24px (diff 3.3), not down (35.5).
- **Rebase conflict:** the other machine pushed Kaleidoscopes, Raptor Run, Oscilloscope and Cymascope (main was 6 behind). `tools/lab-server.mjs` conflicted in the header comment and startup log. Both were kept, and the Controls menus now list all four labs.
