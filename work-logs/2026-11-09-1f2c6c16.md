**Halftone renderer** (`halftone.js`, new)
- Draws each band onto a `<canvas class="halftone">` inside its section. The canvas is centred on the edge with the section above and reaches `height/2 + bleed` px either side. `bleed()` grows with the distortions so nothing gets clipped. It sets `--halftone-reach`, which `styles.css` uses for section padding and the cover height. The CSS gradient dots were removed, so without JavaScript the band is a straight edge.
- Method: every pixel finds its nearest dot centres on a screen (grids: offset, hex or square; shapes: round, square, diamond or line). Dot radii come from a sorted distance-to-nearest-dot table, so colour coverage ramps 0 → 1 across the band (dots grow, merge, then the holes close). With "one size per dot" on, each dot takes its size from the coverage at its own centre.
- Settings (`DEFAULTS`): height, start/end, curve, cell (shown in the lab as density, in rows), dotSize, grid, shape, perDot, angle, stretch, softness; wave, ragged edge, mottle, warp, sizeTop/sizeBottom (perspective), jitter and seed; animation settings animate (mottle strength wanders between mottleMin and mottleMax), flow (px/s, sideways travel), heaveAmp/heaveLen (swells that rise and fall), rise (px/s, mottle drifts up), morph (mottle shapes per second), animPeriod and animFps. `shift` and `time` are internal, set per frame by `at(cfg, seconds)`.
- `renderer(canvas)` uses a WebGL2 fragment shader that ports the same maths, noise hash included, so output matches. It falls back to the CPU `mask()` + `paint()` path when WebGL2 is missing, and that path draws a still band only. `animate()` uses requestAnimationFrame capped at animFps (default 60).
- `mount(sections, cfg)` builds the home page canvases. It redraws on width change, animates only bands an IntersectionObserver reports as visible, pauses when the tab is hidden, and never animates under `prefers-reduced-motion`.

**Second round: no lockstep tiles** (`split-flap.js`)
- Cause: in later spins every tile started from its current letter and stepped through the drum in the same order, at the same rate, at almost the same moment, so neighbours (especially blanks) flipped through identical letters together. The first spin was fine because each tile opens on a different random letter.
- Fix in `spinModule()`: the first flip lands on a random letter (the spin is the last `flips` letters before the target, flips random between minFlips and maxFlips), and each tile flips at its own pace (±20% of `flipMs / speed`).
- Measured with a new read-only `states(t)` helper (what each module shows at time t), replaying every later spin at 10 ms steps: side-by-side tiles both mid-flip and identical went from **26.2%** to **1.8–1.9%**, and the longest run of matching tiles from **7** to **2**. A pixel-hash version of the test was rejected because bouncing blank tiles look identical at any timing.

**Second round: guided scroll** (`index.html`, `styles.css`)
- CSS `scroll-snap-type: y mandatory` was tried first and dropped: a short wheel scroll from the top snapped back to 0, because the top was the nearest snap point.
- Replaced with a script. It inserts a `span.project__snap` in each project, one screen tall (minus the nav) and centred in the section. Stops are the top of the page plus each marker's centre aligned with the middle of the area below the nav.
- Wheel (non-pinch, mostly vertical) is taken over: one gesture moves one stop in its direction, and it stays locked until the glide ends and the wheel has been quiet for 220 ms, so trackpad momentum doesn't skip projects. Panels that scroll on their own are left alone.
- Touch: swipes over 24px move one stop. Keys: Down/PageDown/Space next, Up/PageUp/Shift+Space previous, Home/End first and last. Anything else that moves the page (scrollbar, links, find in page) settles on the nearest stop after 180 ms.
- Glide: easeInOutCubic, 650–1100 ms by distance, `behavior: 'instant'` per frame because `html` has `scroll-behavior: smooth`. Off under reduced motion.
- Tested stops at 1440×900: 1138, 2835, 4532, 6229, 7926. Short wheel, a 45-event momentum flick, arrow keys, Home and a scrollbar-style jump all landed exactly on a stop.

## Challenges and how we solved them
- **Screenshotting below the fold:** a headless `--screenshot` with a tall window also made the cover taller, because it's sized in `svh`, and `#hash` URLs didn't scroll. Fixed with a small Chrome DevTools Protocol script in the session scratchpad (`shot.mjs`, `anim.mjs`, `gl*.mjs`) that navigates, scrolls, evaluates JavaScript and captures.
- **"Symmetrical" misunderstood twice:** first the band was centred on the section edge (kept). Then a mirror style, with upper-colour dots shrinking into the lower colour, was added and reverted at the user's request. The centring stayed.
- **Dot size above 1 left stray specks:** scaling the radius back to 1 near the end made it shrink. Sizes above 1 now advance coverage instead (`t × dotSize`), so dots only ever grow.
- **Animation widened and narrowed the band:** animating the mottle scale zoomed the pattern about the centre. Scale wandering was removed and replaced with heave (vertical swells). Only flow moves anything sideways.
- **Frame rate:** the CPU renderer ran 10–14 fps even off the main thread in a worker. It was rebuilt as a WebGL2 shader and now holds 60 fps in the lab with all five bands at 4× zoom. GPU and CPU output differ by under 0.2% mean, checked with `readPixels` against `mask()`.
- **Checking the direction of rise:** per-pixel comparisons failed because the dots stay on their grid and only resize. Averaged over 24px patches, one second's frame matched the previous frame shifted up by 24px (diff 3.3), not down (35.5).
- **Rebase conflict:** the other machine pushed Kaleidoscopes, Raptor Run, Oscilloscope and Cymascope (main was 6 behind). `tools/lab-server.mjs` conflicted in the header comment and startup log. Both were kept, and the Controls menus now list all four labs.
- **Board and band stutter together (post-merge):** holding the band still until the board finished worked, but the user disliked the wait. Measuring each on its own showed the board's 10 motion-blur samples were the whole cost. Cutting to 4 samples gave 60 fps with both running.
- **"EXPERIENCE DESIGNER" doesn't fit 12 columns with padX 2:** rather than widening the board, the home page uses padX 1 and centres every message block, which keeps the board's size and the name's position.
- **Restart icon glyph:** ↻ isn't in Geist and fell back to a thin system glyph. Icons are now drawn from SVG paths on the tile.
- **First replay test reported the button at 0 s:** the poll read `hidden` before the button existed (`undefined` is falsy). Fixed by waiting for `hidden === false`.
- **Lockstep tiles:** see "No lockstep tiles". The pixel-hash metric gave misleading results (3% before and after); measuring displayed characters showed the real 26% → 2% change.
- **Native scroll snap went backwards:** mandatory snapping returned short scrolls to the top. A direction-aware script replaced it.
- **Rebase at ship:** origin/main had moved 2 commits ahead (Spectrogram from the other machine). The new branch rebased cleanly with `--autostash`.
- **Periodic "lined up" band:** see "No more lines up cycle" above. The fix was to make mottle strength vary along the band so it can never flatten everywhere at once.

## Lessons learned
- The user wants the band animating from the start, not delayed behind the board intro. A deferral that hides the problem isn't acceptable; fix the cost instead.
- The user judges motion by eye on the real page. Numeric checks (shifted-frame comparisons, raggedness over time) are how Claude confirms direction and regularity, but the user's feedback decides.
- A global animated parameter (such as mottle strength for the whole band) produces visible cycles. Vary it by position too.
- Wording like "symmetrical" can be ambiguous; the user reverted a mirror-dot interpretation, so confirm before building a big style change.
- Measure each animation on its own before combining or deferring. Here the expensive part was the board's motion blur, and a 10 → 4 sample cut fixed it outright.
- Spins that start from a shared state need explicit randomness (random first letter, per-tile pace), or neighbours march together.
- Measure what the viewer sees (displayed characters), not pixel hashes, when judging visual sync.
- The user tunes the board in the Split-Flap Lab and saves over versions, which can undo performance defaults. Check `split-flap-versions.js` before shipping.
- For "guided" scrolling, native CSS mandatory snapping picks the nearest point, not the next one in the scroll direction; a direction-aware script is needed for the feel the user wants.
