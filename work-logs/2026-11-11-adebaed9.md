## Challenges and how we solved them

- **Headless Chrome phone screenshot looked clipped at 390px.** Headless Chrome enforces a minimum window width (~485px). Measured inside a 390px-wide iframe instead; no element past the edge.
- **Impeccable design hook findings on the design system page:**
  - `dark-glow` (#6eaaff): the static spark's glow inherited from `styles.css`/`spark.js`, a deliberate Button Lab effect. Suppressed with `ignore-value dark-glow "*" --file tinkering/design-system/index.html`.
  - `repeated-container-text` ("Tinkering" ×4): the nav button state sheet, intentional. Suppressed the same way; this hides any repeated-text finding on that page.
  - Cramped top padding on the two sample project sections: false alarm, their top padding is set at runtime by `halftone.js` (halftone reach + 48px). Suppressed; this hides the check page-wide.
  - All ignores live in `.impeccable/config.json`, untracked.
- **Spacing outlier check:** between 600 and 800px the nav doesn't fit on one row and the page scrolls sideways (769px wide at 700px; was 799px before the spacing changes). Pre-existing; not fixed.
- **Design system page after adding new sections:** halftone sample covered the text above it and was cut off at the column edges; the full-width sample then made the page wider than the window. Fixed by giving the halftone room, making `main` full-width and splitting the text column around the sample bands, and fixing the replay button styling. Overflow rechecked clean.
- **Menu specimen crash:** the Controls menu specimen on the design system page threw in `nav.js`, killing the theme toggle; detached the specimen from `nav.js`.
- **lil-gui colours in folders:** see greyscale section above.

- **Split-flap board collapsed on the alternatives page.** The board's CSS lives in `styles.css`, which those pages don't load; copied the rules to `tinkering/alternatives/board.css`.
- **Lab row text didn't reach the landing page.** The home page built its rows from its own markup; it now reads the active version's lines.
- **Halftone canvas made the page 2,865px wide and hung below the page end.** The band's `::after` spans ±100vmax and relied on `main` clipping; outside `main` it needs its own clipping frame (`.endframe`, `overflow: clip`, pulled up by the halftone's reach).
- **Headless Chrome virtual time doesn't advance CSS animations or rAF reliably inside iframes.** Two prototype variants looked broken when they weren't. Real-time captures were taken by delaying the wrapper page's load event with an image from a small local server that sleeps.
- **`llms.txt` returned 404 locally** until the dev server was restarted: it reads `.vercelignore` once at start.

## Lessons learned

- Headless Chrome `--window-size` can't go below ~500px wide; use an iframe wrapper to check true phone widths.
- The `--chip-*` and role tokens are unregistered custom properties, so `getComputedStyle(...).getPropertyValue` returns raw `color-mix(...)` text; paint onto an element and read its computed `color` for a real value.
- User preferences: design system public on the site but `noindex`; separate branch per feature, merged to `main` only on request; pushing `main` waits for an explicit yes (it deploys to production).
- When snapping to a scale, add a missing step (4px) rather than visibly moving things.
- Greyscaling UI chrome keeps lightness so contrast and selected state still read; keep colour only where it carries information.
- `ignore-value` hook suppressions are page-wide, so they can hide real problems of the same kind on that page.

- The user prefers restraint: one signature object (the board), small plain text around it, colour used sparingly. Gold accents and "now showing" labels were rejected; lighter flaps and no re-spin were preferred.
- Anything the lab saves should drive the landing page without extra steps.
- zsh doesn't word-split `set -- $var`; use explicit function arguments in loops.
