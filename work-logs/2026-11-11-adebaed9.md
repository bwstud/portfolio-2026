## Challenges and how we solved them

- **Headless Chrome phone screenshot looked clipped at 390px.** Cause: headless Chrome enforces a minimum window width (layout viewport came out 485px). Fix: measured inside a 390px-wide iframe instead; `scrollWidth` equalled `clientWidth` (375 after scrollbar), no element past the edge.
- **Impeccable design hook findings on the page:**
  - `dark-glow` (#6eaaff): the static spark's glow colour inherited from `styles.css`/`spark.js`, a deliberate Button Lab effect. Suppressed with `ignore-value dark-glow "*" --file tinkering/design-system/index.html` (the rule has no extractable value).
  - `repeated-container-text` ("Tinkering" ×4): the nav button state sheet, intentional. Suppressed the same way, scoped to this page; note it hides any repeated-text finding on this page.
  - Both ignores live in `.impeccable/config.json`, which is untracked.

## Lessons learned

- Headless Chrome `--window-size` can't go below ~500px wide; use an iframe wrapper to check true phone widths.
- The `--chip-*` and role tokens are unregistered custom properties, so `getComputedStyle(...).getPropertyValue` returns the raw `color-mix(...)` text; paint onto an element and read its computed `color` to get a real value.
- The user wants the design system public on the site but `noindex`, and wants separate branches per feature, merged to `main` only on request; pushing `main` waits for an explicit yes.
