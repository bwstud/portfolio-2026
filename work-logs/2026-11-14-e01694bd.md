## Challenges and how we solved them
- **User saw the old screenshot instead of the wall.** The server on 8080 was from the night before and read `.vercelignore` once at start-up, so it returned 404 for `drift-wall.js` and `drift-wall.css`. Fix: stopped and restarted the server.
- **Branch created from the wrong base.** Created `groom_lake_case_study` from `cover-materials` first, then rebased onto `main` and force-pushed.
- **Blank tiles in headless stills.** Believed to be the headless capture; the wall on a bare page loaded every image, and measuring column positions ten seconds apart confirmed the drift.
- **Unreliable positions in headless screenshots.** Switched to driving headless Chrome over its debugging port (CDP helper in the scratchpad) to measure real layout and take true screenshots; later extended with real mouse movement to test hover and peek behaviour.
- **Headless Chrome doesn't run hover or animation frames in virtual-time mode**, and the Chrome extension wasn't connected, so early hover and parallax were never seen live.
- **Footer halftone ending in a solid block.** Present in `main` already: the Matte commit (80a27ae, Nov 13) changed `halftone.js` to paint only the "to" colour, but the fill behind still started at the edge. Found by hiding the fill. Fixed in `matte-page.css`.
- **Board moved 4px after the styles moved to `board.css`.** An inline media rule that had been losing the cascade started winning. Removed it; the plate is back at 32px.
- **Lines on a lifted flap.** See "Flap drawing fix". Holding a flap still on the brightened row exposed faults that predated the partial lift.
- **Keeping the fold's parts in step.** Height animates on the main thread and transforms on the compositor, so all were derived from one registered property.
- **Mobile tap sounds.** Not reproducible here (no phone). The Web Audio rewrite is a best-guess fix for per-press `<audio>` clones going through a phone's media player.
- **claire.io** renders client-side, so a fetch showed nothing; headless Chrome with a real mouse showed the panel and peek pattern.
- **Slow last second of the arrival.** A single cubic-bezier cannot ease normally then creep for a second. First answer: a main ease joined to a settle at matched speed; the user dropped it. Second answer, kept: bend the bezier's own progress by a power at each end, which stays one smooth curve.
- **Removing the settle exposed stale handles.** "Tune 1" held arrival handles that had been ignored while the settle was on; with it gone they produced an overshoot. Fixed by removing them from the saved version when the user asked for a plain ease in and out.
- **Board opening under the sheet.** See "Board vs. panel fix".
- **Reset buttons wrapping fader names.** Accepted as a side effect rather than widening the panel.

## Lessons learned
- The dev server (`tools/lab-server.mjs`) only reads `.vercelignore` at start-up. Any new shipped file needs a restart. I offered to make it re-read the file when it changes; the user hasn't taken that up.
- Stills from headless Chrome can mislead for layout and animation. Measure through the debugging port, and say plainly what was not seen live. A real-mouse CDP run is the way to test hover, peek and pointer-dependent state bugs.
- The user prefers action over questions when they say "Just start", and for server and file tasks inside this repo they expect me to do it ("You stop it and start it").
- The user steers by image and reference component or site: match the example's behaviour, then iterate on brightness, size and timing.
- The user reverses experiments quickly (latching nav). Keep such changes self-contained so they come out cleanly.
- A shared stylesheet beats a lab copy: the lab's board must show what the site shows, so the finish lives in one file.
- The user wants every tunable exposed in a lab, with a typed number, a per-control reset, and separate curves per motion; build labs with those from the start (now in `CLAUDE.md` and memory).
- Pointer-driven state can be confused by layered UI: anything that reacts to hover must ignore the pointer while a modal covers it.
- On `/pick-ui-library`: the curated list had no good fit for the wall. Motion would only make sense for an interactive version. I recommended staying with plain CSS.
