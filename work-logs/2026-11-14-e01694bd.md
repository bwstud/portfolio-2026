## Challenges and how we solved them
- **User saw the old screenshot instead of the wall.** The server on 8080 was the one from the night before, and it read `.vercelignore` once at start-up, so it returned 404 for `drift-wall.js` and `drift-wall.css`. The page then fell back to the old image. Fix: stopped and restarted the server.
- **Branch created from the wrong base.** I created `groom_lake_case_study` from `cover-materials` first, then rebased it onto `main` and force-pushed.
- **Blank tiles in my headless stills.** I believe this is the headless capture. The wall on a bare page loaded every image, and measuring column positions ten seconds apart confirmed the drift.
- **Unreliable positions in headless screenshots after moving the board.** Switched to driving headless Chrome over its debugging port to measure the real layout and take true screenshots at 1710px and 1200px.
- **Headless Chrome doesn't run hover or animation frames**, and the Chrome extension wasn't connected, so hover and parallax were never seen live.
- **Footer halftone ending in a solid block.** Present in `main` already: the Matte commit (80a27ae, Nov 13) changed `halftone.js` to paint only the "to" colour, but the fill behind still started at the edge. Found by hiding the fill and seeing the canvas held the whole transition. Fixed in `matte-page.css`.
- **Board moved 4px after the styles moved to `board.css`.** An inline media rule that had been losing the cascade started winning. Removed it; the plate is back at 32px.
- **Lines on a lifted flap.** See "Flap drawing fix" above. Both faults predated the partial lift; holding a flap still on the brightened row exposed them.
- **Keeping the fold's parts in step.** Height animates on the main thread and transforms on the compositor, so they were all derived from one registered property instead of separate transitions.
- **Mobile tap sounds.** Not reproducible here (no phone). The Web Audio rewrite is a best-guess fix for per-press `<audio>` clones going through a phone's media player.
- **claire.io** renders client-side, so a fetch showed nothing; a headless Chrome click on a project link showed the panel pattern.

## Lessons learned
- The dev server (`tools/lab-server.mjs`) only reads `.vercelignore` at start-up. Any new shipped file needs a restart. I offered to make it re-read the file when it changes; the user hasn't taken that up.
- Stills from headless Chrome can mislead for layout and animation. Measure through the debugging port, and say plainly what was not seen live.
- The user prefers action over questions when they say "Just start", and for server and file tasks inside this repo they expect me to do it ("You stop it and start it").
- The user steers by image and reference component: match the pasted example's angle, then iterate on brightness and size.
- The user reverses experiments quickly (latching nav). Keep such changes self-contained so they come out cleanly.
- A shared stylesheet beats a lab copy: the lab's board must show what the site shows, so the finish lives in one file.
- On `/pick-ui-library`: the curated list had no good fit for the wall. Motion would only make sense for an interactive version (speed easing on hover or scroll, drag and fling). I recommended staying with plain CSS.
