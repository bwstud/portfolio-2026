## Lessons learned
- The dev server reads save routes and the deploy allowlist only at startup; restart after adding either.
- Hand-drawn heads from photographs read as a bird's head; a modelled head fixed it. The model lives outside deployed folders and is gitignored.
- Every lab uses Matte, and every numeric control needs a typed field.
- The user judges by eye; much was only checked as stills, never in motion.
- Lab version files are live user data: never restore from a backup; test saving against a copy.
- A silhouette-shaped wall didn't work at the stage sizes we have.
- Confirm where a new asset goes (hero vs. slide-in panel) before wiring it in.
- The user supplies copy as pasted text and wants it word for word; flag likely errors instead of silently fixing them (typos aside).
- Photography and slides inside the product film don't suit the user's taste; the film stays product-only.
- Gradients in 8-bit video band visibly; use flat colours for large backgrounds.
- The user wants rhythm in the film: hard cuts and varied shot lengths; wipes that reveal other layers look ghosted.
- The user prefers hologram letters static and plain: no parallax, no sweep-in, no jitter.
- CSS `brightness` on already-bright antialiased text clips the edge ramp and looks pixelated at 1x.
- When recording a page with a stepped clock, any animation driven by `requestAnimationFrame` timestamps needs the recording clock too.
- The user cares about equal gutters either side of the rail divider.

- Don't add labels, eyebrows, subtitles or subtext the user didn't ask for [confirmed]; offer them instead.
- A page that uses Matte keys without loading `matte.js` gets keys without the filings effect; consider having `matte.js` start itself.
- The site carries only Söhne Buch (400); a heavier Söhne weight would be faux bold unless its font file is added.
