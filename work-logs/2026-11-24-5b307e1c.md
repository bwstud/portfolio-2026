### Tagline ink-in fix for Safari (11-26, shipped in PR #58)

- The user: on a phone the tagline "starts, then quickly freezes", then the whole text block appears fully formed.
- **Cause:** WebKit doesn't repaint an HTML element when the attributes of the SVG filter it wears (`filter: url(#…)`) change, only when it points at a different filter. It was reproduced in simulator Safari with a minimal page.
- **Fix** in `work.html`: `inkIn()` (record titles) and `goo()` (project sheet tagline) give each line two filters and swap between them each frame. `inkIn()`'s clock now advances at most 50ms per frame, so dropped frames slow the ink-in rather than skipping it. WebKit renders these filters on the CPU.
- **Checked:** in simulator Safari the Groom Lake title now goos through its stages (driven by a same-origin wrapper page that scrolls `work.html` in an iframe; the scripted scroll didn't reach Mazlan). Headless WebKit showed no errors. Not checked on a real iPhone.

## Lessons learned

- The user's names: "project name" is the small mono name, "tagline" the large title, "attr tags" the mono tag list, "info cards" the fields. In the 11-27 opening requests, the user also called the project name ("GROOM LAKE") the "title".
- Groom Lake's "intro montage" / "hero montage" is the film at the top of the project sheet, not the drift wall.
- The user doesn't want scroll speed or the pointer moving ambient pieces. Entrances should be tight and in reading order.
- For the page's opening, the user wants everything (board, wall, rail, record text) to read as one move: blur plus fade from invisible, the name blurring in rather than sliding, name and tagline finishing together, and the text finishing around when the wall does. The rail staggers slightly and settles with the board. Not yet recorded in the taste profile.
- When two scripts animate one block, give them one clock. A CSS animation beside a script-driven one that caps its frame step will drift under load.
- Don't start many videos under a large animated blur.
- Measuring a sticky element's position includes the scroll distance once it's stuck; measure its un-stuck position.
- Menu rules: header aligned and proportional to rows; seams and lamps; never scroll; no magnetic surface on rows.
- No hard or solid edge in shading under a docked element.
- Board: leaving content fades before the frame shrinks; hover lights only what the pointer is on; highlights fade; hit areas span a row's gaps.
- The painted metal text was rejected; a one-time glint was what the user chose to try.
- Changing Matte changes every menu that uses it. Say so when shipping.
- Moving screens: no cursor, every screen moves, loops lean toward 12s, light and dark mixed. The user notices choppiness and badly fitted device frames.
- For recorded app motion (scrolls, pushes, sheets), keep the capture's 60fps through every stage. Don't reduce frame rate in masters or encodes.
- Prototype and app source are the user's: drive them, never edit them.
- For interface video, AV1 at the same SSIM was about 40–65% of H.264's size here; use it only with hardware decoding when many play at once.
- A UI-test driver can record the iOS simulator without Accessibility permission or taking the mouse.
- Don't run encodes while the simulator is recording; extra CPU load can make captures stutter.
- Don't edit a clip list while a batch is reading it. In shell loops, keep the recorder from consuming the loop's stdin.
- When shipping from a branch made from main, say which uncommitted changes are **not** going out.
- Paper holds a fuller set of Blackbird screens (about 75, with dark mode) than the reel's assets. Paper exports go to `~/Downloads`.
- Safari: an animated SVG filter on HTML needs its `filter` reference changed to force a repaint. Chrome-only testing won't catch this.
- After lifting a 3D-transformed element to a larger size, make sure Chrome re-rasterises it, or it stays soft.
- On 3D-tilted, coplanar elements, don't rely on browser hit testing; map the pointer onto the plane. Test hover at many points per target, corners included.
- When an element is moved out of its container, check for CSS that depends on the container. "Playing" in script isn't the same as visible; compare what's on screen.
- The user preferred one combined motion for the pick-up over separately controlled rise and turn. Not yet recorded in the taste profile.
- Keep raw recordings: they allowed larger encodes without re-filming.
- For local testing of video-heavy pages, use a Node static server, not Python's.
- An "in view" margin for preloading shouldn't also decide what plays. IntersectionObserver-gated media should start as off screen.
- On a 120Hz Mac, Chrome can read 30fps while videos play without the page being overloaded; check main-thread load too.
